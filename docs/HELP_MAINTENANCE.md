# Full Help maintenance

`docs/help/en.json` is the authoritative English master. Its chapter and paragraph IDs are stable. `docs/help/ENGLISH_MANUAL.md` is its readable rendering. `docs/help/recovered-12.3.0-en.txt` preserves the full original guide and provenance commit/hash. The runtime `locales/en.json` Help is a generated copy; do not edit it instead of the master. The original guide is retained inside media_sorter.py as a historical emergency fallback, not as a second editable master.

Edit paragraph text in the master, keeping IDs when content is updated and adding a new ID for a new section. Run `python tools/sync_help_master.py` to rebuild bodies, English runtime Help and the readable master. Run `python tools/translate_help.py --provider bing --workers 4` to translate only changed Help paragraphs. The tool uses the existing locale UI labels as a glossary and preserves chapter links, parameter placeholders, keyboard shortcuts, file names and technical references. European and Brazilian Portuguese use separate regional targets. Paragraph caches are local and resumable. Translation never modifies the existing strings/literals dictionaries.

The translator uses machine translation; structural completeness does not certify fluent, culturally appropriate language. Review representative detailed chapters and RTL rendering and retain that distinction in release reports. Do not claim a professional human linguistic review of all languages without one.

Run `python tools/validate_help.py --report docs/HELP_VALIDATION.json`. It verifies all language IDs, master hashes, exact chapter and paragraph coverage/order, nonempty text, suspiciously short paragraphs, English leftovers, chapter references, placeholder markers, expected direction and balanced bidi isolation. CJK and other compact languages have lower length thresholds. English residue warnings need review because paths, UI names and codecs legitimately remain technical references. Missing content is a hard error, never an acceptable shorter translation.

The application falls back to the full English chapter if a selected Help chapter lacks the expected paragraph IDs/body or master hash. A short summary cannot override the master. The UI generator refuses full pack regeneration once schema 2 Help exists; UI-only filling preserves existing Help. Both builders run full Help validation.

Linux Tk 8.6 uses rtl_display.py for Arabic/Hebrew/Urdu/Persian display. Dictionary/master text stays logical. Wrapping precedes bidi conversion; character mappings restore exact search highlights and links. Windows keeps native rendering. Keep the shaping/bidi dependency licences with releases. Automated RTL tests cannot replace native-speaker and real-desktop review.

`python tools/smoke_test_gui.py --report docs/GUI_SMOKE_WINDOWS.json` opens isolated real Tk windows for every language, generates disposable media, checks recursive scanning and image/video sorting, Smart Collections, all chapters, clickable index navigation and RTL alignment. On Linux run it inside xvfb-run for headless integration tests. Headless tests do not prove desktop drag/drop, audio, Trash, driver acceleration, or perfect visual layout. For interactive visual review use `python tools/inspect_help.py ar` (or he/ur/fa). It never changes personal application settings.
